## Commands

```bash
npm run dev          # Dev server on port 8080 (GitHub Pages base path)
npm run dev:docker   # Dev server with Docker base path (/)
npm run build        # Production build → docs/ (GitHub Pages)
npm run build:docker # Docker build → docs/ with base path /
npm run build:dev    # Development build → docs/
npm run preview      # Preview production build locally
npm run lint         # Run ESLint
```

No test framework is configured.

## Architecture

Single-page React 18 + TypeScript portfolio, built with Vite and deployed two ways:
- **GitHub Pages**: base path `/Gurekam-Portfolio/`, output to `docs/`
- **Docker**: base path `/`, served by Nginx on port 80 (multi-stage Dockerfile)

The base path is selected at build time via `import.meta.env.MODE` in `vite.config.ts`.

### Source Structure

```
src/
├── App.tsx              # Root: React Router, QueryClientProvider, TooltipProvider, Toaster
├── pages/Index.tsx      # Main page — composes all section components in order
├── components/          # One file per portfolio section (Hero, Experience, Skills, Projects, etc.)
│   └── ui/              # shadcn/ui primitives (Radix UI + Tailwind) — do not edit manually
├── lib/
│   ├── utils.ts         # cn() helper for class merging (clsx + tailwind-merge)
│   └── resume.ts        # Structured resume data consumed by section components
└── hooks/               # use-mobile.tsx, use-toast.ts
```

### Key Patterns

- **All portfolio content** (experience, skills, projects, certifications) lives as static JS objects — either in `src/lib/resume.ts` or inline in the relevant section component. There is no API or backend.
- **Path alias**: `@/` maps to `./src/` — use it for all internal imports.
- **Styling**: Tailwind utility classes with a custom DevOps theme (blue/cyan/purple/green palette) defined in `tailwind.config.ts`. Custom animations (`fade-up`, `glow`, `float`) and dark mode (`class` strategy) are configured there.
- **shadcn/ui**: Components in `src/components/ui/` are generated by the shadcn CLI — regenerate rather than hand-edit them. Config is in `components.json`.
- **Navigation**: The navbar in `Navigation.tsx` uses `document.getElementById(...).scrollIntoView()` for smooth in-page anchor scrolling — there are no hash routes.
- **Mouse effect**: `MouseLightEffect.tsx` renders a canvas-based spotlight that follows the cursor — it is a purely visual effect with no state impact on other components.

### TypeScript

Loose configuration (`noImplicitAny` and `strictNullChecks` are **disabled**) — avoid tightening these without testing across all components.
